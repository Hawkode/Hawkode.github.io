Home Lab Project

Home Network Build with UniFi Dream Router 7

This project replaced a single ISP router with a UniFi Dream Router 7 (UDR7) to build a segmented, monitored home network. The work covered initial setup, VLAN design, firewall rules between networks, Wi-Fi configuration across multiple bands, remote access over WireGuard, and intrusion detection.

The line is a symmetrical 900/900 Mbps fibre service with a static IPv4 address. The ISP router was moved to modem mode to remove double NAT, so the UDR7 holds the public address and performs all routing, firewalling, and VPN termination.

Privacy note: SSID names, exact IP reservations, credentials, and the public address have been removed or replaced with representative values.

Problem

Why This Project Was Needed

The ISP router handled routing and Wi-Fi on a single flat network, with every device on the same broadcast domain. That left no way to separate trusted machines from untrusted ones and almost no visibility into what was connected.

Before

  • One flat network for every device, trusted and untrusted alike.
  • No VLANs, no inter-network firewall rules.
  • Upload speed a small fraction of download.
  • Double NAT blocked inbound connections and clean remote access.
  • Little visibility of clients, traffic, or threats.

Target State

  • Separate VLANs for Main, Kids, IoT, Guest, and Servers.
  • Firewall rules isolating untrusted networks from Main.
  • Full symmetrical 900/900 line with the UDR7 as the only router.
  • Secure inbound access over WireGuard only.
  • IDS/IPS and client visibility across the whole network.

Design

Network Topology

The UDR7 sits behind the ISP modem and terminates the public address. Each network is a separate VLAN with its own subnet and firewall policy. Trusted devices sit on Main; everything that does not need to reach Main is pushed onto its own segment.

Single Routed Gateway

The UDR7 holds the public IP and routes every VLAN, replacing the ISP router's flat network with segmented, policy-controlled paths.

Inter-VLAN Firewall

Main can reach IoT to control devices; untrusted networks cannot initiate connections back to Main. Guest is isolated to internet access only.

Segmentation

VLAN and Wi-Fi Design

Five networks cover the household, with four Wi-Fi names (Servers is wired only). A device gets its own VLAN when it needs different firewall rules from everything else; groups that would share the same rules stay together.

NetworkPurposeWi-FiNotes
MainAdults' phones, laptops, main PCYes WPA2/WPA3; 6 GHz band requires WPA3
KidsChildren's devicesYes Content filtering and time schedules
IoTTVs, cameras, smart plugsYes WPA2 with 2.4 GHz enabled for legacy devices
GuestVisitorsYes Client isolation on, internet only
ServersSelf-hosted services, automationNo Wired only, fixed IPs, reached over WireGuard

Fixed addresses are set as DHCP reservations on the UDR7 for the router, the main PC, and anything that is connected to (servers, NAS, printer, cameras). Everything that only connects outward stays on DHCP. Keeping all reservations in one place on the router avoids address clashes and keeps DNS and gateway settings consistent when they change.

Remote Access

Secure Inbound Connectivity

Moving the ISP router to modem mode removed the double NAT that had been blocking inbound connections. With the UDR7 holding the public static address, remote access could be set up properly.

WireGuard VPN Server

  • Encrypted tunnel for reaching home services from outside.
  • The only inbound path; no services exposed directly.
  • Clients routed to the Servers VLAN with fixed IPs.

UniFi Teleport

  • One-tap remote access from the UniFi app.
  • Useful for quick management without a full VPN profile.

Family sites are managed through UniFi Site Manager. Each household owns its own console and invites admin access, rather than placing every router under one account, so each owner keeps control and can revoke access at any time.

Security Rationale

Attack, Detect, Harden

The design choices map directly to how a flat network gets abused and how segmentation limits and surfaces that abuse.

  • Lateral movement: on a flat network, one compromised IoT device can reach every other host. Blocking IoT and Guest from initiating connections to Main removes that path. The UDR7's firewall logs show denied cross-VLAN attempts.
  • Physical port abuse: an outdoor PoE camera run is a network socket on the outside of the building. Pinning that port to the IoT VLAN means unplugging the camera and connecting a laptop reaches nothing on Main.
  • Exposed services: no port forwards to internal hosts. Inbound access is WireGuard only, so there is no listening service on the public IP to scan or brute-force.
  • Detection: IDS/IPS inspects traffic for known signatures, and client and traffic visibility makes an unexpected device or an outbound beacon from the IoT VLAN stand out against a normal baseline.

Testing the Segmentation

Each firewall rule was tested from the segment it was meant to restrict. A client placed on an untrusted VLAN was used to confirm it could not reach the gateways or hosts of other networks, while the same targets stayed reachable from their own segment.
