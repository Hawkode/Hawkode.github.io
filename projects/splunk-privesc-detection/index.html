Security Lab

Detecting Privilege Escalation in Splunk

This lab is the defender's half of my Windows Privilege Escalation write-up. It takes the same techniques and builds the detections: the Windows and Sysmon events they generate, the Splunk searches that surface them, and the saved alerts that turn a line in a log into a signal someone acts on.

Scope: a home SOC lab. A Windows VM runs Sysmon and command-line process auditing; logs ship to Splunk, where the searches below run as scheduled alerts. The SPL is illustrative: index names and field names depend on the add-ons in use (Splunk Add-on for Microsoft Windows, Sysmon TA), so treat them as a starting point to tune, not copy-paste rules.

Design

The Detection Pipeline

Detections are only as good as the data under them. The chain is: generate the events on the endpoint, ship them to Splunk, search them, and alert. If command-line auditing and Sysmon are not on, most of these searches have nothing to match.

Detection

Named-Pipe Impersonation (Potato)

The potato family creates a named pipe to coerce and impersonate a SYSTEM token. A service account opening an unusual pipe is the signal. Sysmon Event ID 17 captures the pipe creation.

# Sysmon pipe create under a service account index=win_sysmon EventCode=17 | search User IN ("NT AUTHORITY\\NETWORK SERVICE","NT AUTHORITY\\LOCAL SERVICE","*\\IUSR","*MSSQL*") | stats count values(PipeName) AS pipes values(Image) AS images min(_time) AS first_seen BY host, User | where count > 0

Maps to ATT&CK T1134 (Access Token Manipulation). Tune by baselining the pipes your legitimate services open, then alert on the rest.

Detection

SAM / SYSTEM Hive Theft

Copying the registry hives for offline credential cracking shows up in the command line of reg.exe, esentutl.exe, or vssadmin.

# Hive export via reg save / esentutl / VSS index=win_security EventCode=4688 | search (New_Process_Name="*\\reg.exe" AND Process_Command_Line="*save*sam*") OR (Process_Command_Line="*reg* save *hklm\\sam*") OR (New_Process_Name="*\\esentutl.exe" AND Process_Command_Line="*vss*") OR (Process_Command_Line="*vssadmin* create shadow*") | table _time, host, Account_Name, New_Process_Name, Process_Command_Line

Maps to ATT&CK T1003.002 (OS Credential Dumping: SAM). High fidelity; legitimate hive exports are rare outside backup software.

Detection

Rogue Services and MSI Abuse

# New service installed index=win_security EventCode=7045 | table _time, host, Service_Name, Service_File_Name, Service_Account | sort - _time

Rogue Service

A service pointing at a script or a binary in a user-writable path is a classic escalation and persistence step. ATT&CK T1543.003.

# AlwaysInstallElevated MSI as SYSTEM index=win_security EventCode=4688 New_Process_Name="*\\msiexec.exe" | search Process_Command_Line="*/quiet*" OR Process_Command_Line="*/qn*" | stats count BY host, Account_Name, Process_Command_Line

MSI Abuse

A non-admin installing an MSI silently points at the AlwaysInstallElevated misconfiguration. ATT&CK T1548.

Operations

From Search to Alert

  • Each search is saved as a scheduled alert, run on a short interval over a rolling window.
  • Throttling (suppression) stops one noisy host from firing the same alert repeatedly.
  • Known-good activity is allowlisted first: backup software that touches hives, deployment tools that install MSIs, admin jump hosts.
  • Each alert carries the ATT&CK ID and the host, so triage starts with context instead of a bare event.

The goal is a short list of high-fidelity alerts, not a wall of noise. A detection that fires fifty times a day for legitimate admin work gets muted and stops being a detection, so tuning is the real work, not writing the first search.
