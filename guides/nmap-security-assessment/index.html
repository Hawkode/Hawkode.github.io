Security Guide

Nmap Security Assessment

This guide documents a basic security assessment workflow using Nmap. The goal is to identify exposed services, review common risks, and record practical remediation steps for services such as FTP, SSH, Telnet, and SMB.

The assessment focuses on authorised scanning only. Nmap should only be used against systems, networks, or lab environments where permission has been granted.

Purpose

Assessment Objectives

The purpose of this assessment is to understand what services are exposed on target systems and identify possible security weaknesses.

Discover Open Ports

Identify whether common services such as FTP, SSH, Telnet, and SMB are reachable on the target systems.

Identify Service Versions

Use service detection to understand what software and versions are running on exposed ports.

Review Security Risks

Look for risky services, weak configurations, legacy protocols, and exposed network access.

Document Remediation

Record findings clearly and provide practical recommendations to reduce risk.

Setup

Install and Verify Nmap

Nmap can be installed on most Linux distributions and macOS. After installation, verify that the command is available before starting the assessment. 

sudo apt install nmap

nmap --version

On a controlled lab machine, this confirms that Nmap is ready to run basic discovery, service detection, and script-based checks.

Scope

Define the Target Scope

Before scanning, define the approved target scope. This may be a small list of hosts or a lab subnet. 

export TARGETS="192.168.1.1 192.168.1.2 192.168.1.3"

For a lab subnet, the scope can be defined like this: 

export TARGETS="192.168.1.0/24"

Keeping the scope clearly defined helps avoid scanning systems that are not part of the assessment.

Scanning

Scan Key Services

This scan focuses on common services that can introduce security risk if they are exposed or misconfigured. 

nmap -p 21,22,23,445 -sV -T4 $TARGETS

-p 21,22,23,445 scans FTP, SSH, Telnet, and SMB.

-sV attempts to identify service versions.

-T4 uses faster timing for lab or controlled environments.

Vulnerability Checks

Use Nmap Scripts

Nmap Scripting Engine checks can help identify known issues and risky service configurations. 

nmap --script vuln -p 21,22,23,445 $TARGETS

For SMB-specific checks, the scan can be narrowed to SMB scripts: 

nmap --script smb-vuln* -p 445 $TARGETS

Script results should always be reviewed carefully. Findings should be validated before being treated as confirmed vulnerabilities.

Deeper Review

Comprehensive Scan

A more detailed Nmap scan can be used to collect extra information such as operating system guesses, service details, script output, and traceroute information. 

nmap -A -T4 $TARGETS

This type of scan is useful in a lab or approved assessment, but it should be used carefully because it is more active than a simple port scan.

Findings

Example Risk Findings

FTP - High Risk

Anonymous login or outdated FTP versions can expose files and allow unauthorised access to data.

SSH - Medium Risk

Weak ciphers or older SSH configurations can reduce the strength of encrypted remote access.

Telnet - High Risk

Telnet sends traffic in clear text and should not be used for secure remote administration.

SMB - Medium Risk

Legacy SMB versions such as SMBv1 can increase exposure to known vulnerabilities and should be disabled where possible.

Remediation

Mitigation Recommendations

FTP: Disable anonymous access, restrict permissions, and use secure alternatives or encrypted transfer methods where possible.

SSH: Keep SSH updated, disable weak ciphers, use strong authentication, and limit access to trusted users or networks.

Telnet: Disable Telnet and replace it with SSH for encrypted remote administration.

SMB: Disable SMBv1, use SMBv2 or SMBv3, apply security updates, and restrict file-sharing access.

Compliance Notes

Security and Compliance Alignment

This type of assessment supports basic vulnerability management and network security review activities. It helps identify exposed services, verify technical controls, and document remediation actions.

Vulnerability Management

Regular scanning helps identify systems that may require patching, configuration changes, or further investigation.

Network Security

Reviewing exposed services helps reduce unnecessary network access and improve visibility of the environment.

Technical Review

Documented scan results provide evidence for security review and remediation tracking.

Risk Reduction

Findings can be prioritised by severity so high-risk services can be addressed first.

Outcome

What This Lab Demonstrates

This lab demonstrates the ability to use Nmap for basic network security assessment, service identification, vulnerability checks, risk documentation, and remediation planning.

It also shows how scan results can be converted into practical actions, such as disabling insecure protocols, strengthening service configuration, and improving network visibility.
