Guide

Nmap Security Assessment

This guide documents a basic security assessment workflow using Nmap. The aim is to identify exposed services, review common risks, and record practical remediation steps for services such as FTP, SSH, Telnet, and SMB.

Nmap should only be used against systems, networks, or lab environments where scanning has been authorised.

Step 1

Understand the Assessment Scope

Before running any scan, define exactly which systems are approved for testing. This helps avoid scanning devices that are outside the assessment scope. 

export TARGETS="192.168.1.1 192.168.1.2 192.168.1.3"

For a controlled lab subnet, the scope can also be written like this: 

export TARGETS="192.168.1.0/24"

Step 2

Install and Verify Nmap

Install Nmap on the assessment machine and confirm that the command is available. 

sudo apt install nmap

nmap --version

Verifying the installation first helps confirm that Nmap is ready for port scanning, service detection, and script-based checks.

Step 3

Run a Focused Port Scan

This scan checks common services that can introduce risk when exposed or misconfigured. 

nmap -p 21,22,23,445 -sV -T4 $TARGETS

-p 21,22,23,445 scans FTP, SSH, Telnet, and SMB.

-sV attempts to identify service versions.

-T4 uses faster timing for a controlled lab or approved assessment.

Step 4

Run Vulnerability Script Checks

Nmap Scripting Engine checks can help identify known issues and risky configurations. 

nmap --script vuln -p 21,22,23,445 $TARGETS

SMB can also be checked with SMB-focused scripts: 

nmap --script smb-vuln* -p 445 $TARGETS

Script results should be reviewed carefully and validated before being treated as confirmed vulnerabilities.

Step 5

Run a Comprehensive Scan

A more detailed scan can collect additional information such as operating system guesses, service details, script output, and traceroute information. 

nmap -A -T4 $TARGETS

-A enables OS detection, version detection, script scanning, and traceroute.

-T4 increases scan speed in a controlled environment.

Step 6

Review Common Findings

After the scans complete, review the results and group findings by service and risk.

FTP

Anonymous access or outdated FTP versions can expose data and increase the risk of unauthorised access.

SSH

Weak ciphers or older SSH configurations can reduce the strength of encrypted remote administration.

Telnet

Telnet sends traffic in clear text and should not be used for secure remote administration.

SMB

Legacy SMB versions such as SMBv1 can expose systems to known security risks and should be disabled where possible.

Step 7

Document Remediation Actions

Findings should be written clearly so they can be tracked and remediated.

FTP: Disable anonymous access, restrict permissions, and use secure transfer methods where possible.

SSH: Keep SSH updated, disable weak ciphers, use strong authentication, and limit access to trusted users or networks.

Telnet: Disable Telnet and replace it with SSH for encrypted remote administration.

SMB: Disable SMBv1, use SMBv2 or SMBv3, apply security updates, and restrict file-sharing access.

Summary

Commands Covered

These commands cover installation verification, focused service scanning, vulnerability script checks, SMB-specific checks, and more detailed assessment scans.

Why It Matters

Why This Is Useful

Nmap is useful for understanding what services are exposed on a network and whether those services may introduce security risk.

This type of assessment supports vulnerability management, network visibility, remediation planning, and technical security review.

It also helps turn scan results into practical actions such as disabling insecure protocols, removing legacy services, strengthening configurations, and reducing the attack surface.
