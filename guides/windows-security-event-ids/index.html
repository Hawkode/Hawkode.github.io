Windows Security Event IDs for Detection

A detection is only as good as the events under it. This is the reference I use alongside my privilege escalation and Splunk detection work: the event IDs worth watching, grouped by what they reveal. Security-log IDs are four digits; Sysmon IDs are low numbers from its own Operational log.

Prerequisite

Turn the Logging On First

Most of these are not logged by default. Enable them before expecting the events to appear, ideally through Group Policy across the fleet.

Command-line process auditing: turns on 4688 with the process command line, the single most useful setting.

Sysmon: install with a sound configuration for process, network, file, and pipe telemetry.

PowerShell logging: script-block and module logging for 4104 / 4103.

Forward to a SIEM: an event logged only on the host is gone when the host is wiped.

Why It Matters

Using the Reference

Collecting events is not detecting; the value is in which ones you alert on. The highest-fidelity are the rare, high-impact ones: 1102 (log cleared), 7045 (new service), 4720 and privileged group additions, 4672 to an unusual account, and Sysmon 10 against lsass. Baseline the noisy ones first, then alert on deviation. This maps directly to the SC-200 and CySA+ detection work and feeds the Splunk rules in my detection lab.
